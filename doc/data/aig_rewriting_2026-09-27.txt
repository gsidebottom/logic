# AIG rewriting as a preprocessor for CaDiCaL (2026-09-27)
#
# The box track ended with: tables inside CaDiCaL do not beat CaDiCaL's
# clauses on gate-structured instances (doc/data/boxes_native_propagator
# _2026-09-26.txt §6).  The remaining question about circuit structure
# was whether logic synthesis on the extracted circuit -- ABC's AIG
# rewriting (Mishchenko, Chatterjee, Brayton 2006) and FRAIGing (SAT
# sweeping) -- gives CaDiCaL a better CNF than the one it was handed.
#
# === Method ===
#
# tools/cnf2aig.py: the gate definitions read off the CNF by
# cnf2boxes.extract_gates (AND/OR of any width, XOR2, XOR3, MAJ3 -- each a
# complete Tseitin definition) become an And-Inverter Graph: primary
# inputs are the undefined variables, primary outputs the gate outputs
# that some other clause mentions, gates on definition cycles stay in the
# residual, cones nobody observes are dropped (their definitions are
# always satisfiable).  ABC (github.com/berkeley-abc/abc, built from
# source) rewrites the AIG -- its primary-output functions are preserved
# -- and the result goes back to CNF with the residual appended, inputs
# and outputs keeping their variable numbers.  Two back-ends: one AND at
# a time (Tseitin, 3 clauses per AND), or ABC's cut-based generator
# (&write_cnf, K=8 cuts, minimal covers per cut: it recovers an XOR3 or a
# majority as one 8- or 6-clause block where the Tseitin of its ANDs is
# 3-4x that).  Scripts: resyn2 (balance/rewrite/refactor rounds), resyn2f
# (resyn2 + fraig), dc2f (dc2 + fraig + dc2), and "none" (strash only: the
# round trip).  Equisatisfiability by construction; brute-force self-tests
# against CaDiCaL (random gate circuits + residual clauses, both
# back-ends, three scripts): 1185 + 3144 checks, 0 failures -- after three
# defects: ABC reads only binary AIGER; an empty or output-less AIG makes
# ABC assert (the circuit is dead logic, dropped); ABC's CNF writer forces
# unused objects false, which pinned an unused primary input the residual
# then contradicted (units on inputs are dropped).
#
# Corpus: the 15 gate-structured instances of the balanced set used for
# the wide-cone experiment (§6 there): two prime-factoring rows, md5_48_3,
# ascon, bitvector 31.smt2, agile bench_5078, the hwmcc10 miter, oski
# equivalence checking, the DIMACS sorter, philips, squ_ali, hardware-
# verification k40, summle, bvsub, case18; verdicts known from the
# portfolio.  Plain CaDiCaL 3.0.1 (the same binary) at 600 s on the
# original CNF is the baseline (doc/data/boxes_native_propagator §6);
# every arm's time below is bridge + ABC + CaDiCaL, verdict-checked.
# Runs 3-6 at a time on the 12-core machine.
#

# === Reading ===
#
# 1. The re-encoding alone is the consistent gain.  "none/abc" -- read
# the circuit, structurally hash it, drop dead cones, write it back with
# ABC's cut-based CNF generator, no rewriting -- is faster than plain
# CaDiCaL on 9 of 15 rows counting its own cost, and on 6 of the 7
# unsatisfiable rows (0.31-1.02x, geometric mean 0.64x): the miter and
# oski 0.86x and 0.31x, philips 0.77x, hardware-verification 0.73x,
# case18 0.34x, pyhala 0.86x, bvsub level.  It costs seconds up to 300K
# clauses and 13 s on the 1.5M-clause oski.
#
# 2. FRAIGing (SAT sweeping) collapses the equivalence-checking miters:
# the hwmcc10 miter from 67.5 s to 14.4 s (13 s of it in ABC's own solver
# proving equivalences, 1.1 s in CaDiCaL), oski from 532 s to 65-91 s (up
# to 80 s in ABC, 2-5 s in CaDiCaL; 1,619 conflicts against 3.06 M).
# That is the algorithm those instances are for, and the win is real
# either way: with the preprocessing charged, 3-8x.
#
# 3. Rewriting proper (resyn2, dc2) removes 20-57% of the ANDs (md5 -52%,
# agile -52%, oski -57%, summle -42%) and that does not translate into
# CaDiCaL time in any consistent direction: on the unsatisfiable rows it
# is level with the plain re-encoding except where fraig fires, and
# bvsub's fraig costs 100 s of ABC time for nothing (4x slower).  On the
# satisfiable rows the outcome is trajectory: bitvector 31 from 196 s to
# 14-18 s, agile 92 s to 9-22 s, summle 65 s to 17-22 s, and ascon 29 s
# to 116-427 s, card 4.6 s to 16-104 s, md5 22 s to 33-301 s.
#
# 4. The back-end matters as much as the rewriting.  The AND-at-a-time
# Tseitin inflates XOR- and majority-rich circuits (md5 279K -> 601K
# clauses for the same function, ascon 374K -> 763K) and CaDiCaL pays for
# it (md5 5x, ascon 18x slower on the round trip); ABC's cut-based writer
# recovers the gates as minimal covers (ascon 382K, md5 332K after
# resyn2f) and takes the round trip from 5 wins to 9.
#
# === Verdict ===
#
# Structural hashing plus a cut-based re-encoding is a cheap, consistent
# preprocessing gain on unsatisfiable circuit instances (0.64x geometric
# mean over the seven, none slower than 1.02x); FRAIGing is a large one
# on equivalence-checking miters; AIG rewriting beyond those two is
# noise at the CNF level.  Against the box track's tables, which cost
# 1.5-2x per conflict and lost every unsatisfiable row, this is the first
# use of the extracted circuit that pays, and it pays by handing CaDiCaL
# a smaller, hashed, better-encoded clause set rather than by changing
# what the solver does.  The satisfiable rows say nothing either way.
# What would settle its worth is the same protocol on the full circuit
# classes of the competition set (290 instances), with the re-encoding
# alone and with fraig, scored on solves at the competition cap.
