#   scored on CONFLICTS, not seconds -- deterministic, so 4 instances can run

#     a single instance carried at least four times that week
#   arms run back to back per instance; parallelism is across instances
#   bounded: 6 GB per process, 4 workers, a footprint watchdog at 30 GB
#   every answer checked against the competition's recorded verdict
#
# SOUNDNESS: 310 answers, 0 mismatches.  (suite.log says otherwise on every
# experiment: the harness compared manifest.startswith(solver) -- "SAT"
# .startswith("SATIS") -- backwards.  Second time in a day a verdict check

=== Reading it ===
#
# The balanced set CONFIRMS the old verdicts rather than inverting them.
# Chronological backtracking, the technique I called the likeliest inversion
# (introduced on large industrial instances, dismissed here on tiny classics),
# is HARMFUL on both the easy set (5/20 better, sign test against, losses of
# 115x on graph-isomorphism and 27x on ramseycube) and the hard set (3/14,
# newly solved 5 against newly lost 7).  Stable mode loses on 16/20; its 9
# exact ties are instances that finish before it ever switches on.  Glucose
# restarts are catastrophic (418x on ramseycube), so the EMA default -- the
# one lever that ever moved -- holds at scale.  Shrinking and the grace
# period stay neutral.  The worry about the biased corpus was legitimate;
# on these questions its answers were nonetheless right.
#
# One instance, subgraph-isomorphism, improves under EVERY deviation from
# default (chrono 0.19x, stable 0.11x, glucose 0.08x): an unlucky default
# trajectory on one SAT instance, surfacing as a "win" in every experiment.
# That is what the median and the sign test are for.
#
# The gap decomposition REVERSES on the balanced set -- with two caveats
# that decide how far.  On the 20 competition instances both solvers finish
# we need FEWER conflicts than CaDiCaL on 13, geomean 0.25x, and are faster
# in wall time (0.64x geomean, 0.79x median).  Several are solved in 10-12
# conflicts where CaDiCaL takes 140-9704: that is the engine's own level-0
# simplification, which is part of its core exactly as CaDiCaL's
# inprocessing is part of its own, and the control arm proves no sat.rs
# stage is involved.  But (1) these 20 are the instances WE can solve; the
# 76 we cannot are where the real gap lives and this measurement cannot see
# it; and (2) on the 8 instances with real search (>=300k conflicts in both
# arms) our conflict RATE is 1.3-2.8x slower than CaDiCaL's, not the 1.06x
# the old corpus showed.  "Throughput is not the gap" was a small-instance
# artifact: at competition scale it is one, consistent with the
# cache-hostile Vec<Vec<_>> watch and occurrence layout.  (Rates here are
# under 4-way parallelism in both arms; a serial confirmation follows.)
#
# So the standing on families this engine can solve: it searches well and
# propagates slowly.  On the families it cannot solve at all, nothing here
# says anything, and that remains the honest headline.
