# Why the bundled CaDiCaL 3.0.1 is not the CaDiCaL 3.0.0 on PATH
# (2026-09-18, 120 s cap, one solver at a time, both standalone binaries
# on the same files).
#
# Release 3.0.0 defaults `factor` (bounded variable addition) and
# `preprocesslight` ON; the vendored 3.0.1 defaults both OFF
# (vendor/cadical-3.0.1/src/options.hpp:119,163).  Tested from both sides.
#
# On the five instances every arm answered (php9_8, c3540,
# toughsat_factoring_148s, pyhala-braun-sat-40-4-03, ezfact64_6):
#
#   3.0.1 default      / 3.0.0 default  2.27x slower   (1.29x excluding php9_8)
#   3.0.1 +factor+light/ 3.0.0 default  1.47x slower   (1.62x excluding php9_8)
#   3.0.1 default      / 3.0.0 -f-light 0.64x  -- 3.0.1's core is 1.56x faster
#   3.0.1 +factor+light/ 3.0.1 default  0.65x  (1.26x SLOWER excluding php9_8)
#
# So the options explain 3.0.0's edge exactly on php9_8, c3540 and
# pyhala-40, and not at all on toughsat_148s and ezfact64_6, where each
# version is fastest at its own default.  Enabling them in the vendored
# solver is not an improvement: 4 of 6 instances get slower.  Hence
# `sat -b cadical` runs the vendored release's own defaults, and the
# tables keep quoting the standalone 3.0.0 as the baseline -- the fastest
# CaDiCaL measured here -- rather than the configuration that flatters us.
#
# Read every single-instance ratio against the family's own spread: four
# shufflings of pyhala-braun-sat-40 span 33-65 s for one fixed solver, and
# toughsat_factoring_895s lands at 17.9 s, 108.9 s or a timeout depending
# on arm with no consistent option effect.
