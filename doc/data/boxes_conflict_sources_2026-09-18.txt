# Reading it.
#
# The headroom for bigger or less conic cones is NOT uniform -- it is
# concentrated on exactly the families where the box backend is weakest:
#
#   almost nothing left to absorb   c3540 (0.6-2.5%), c5315 (1.1%),
#                                   toughsat (0.1%), lec_mult (3.1%),
#                                   sum_of_3_cubes (4.8%)
#   real headroom                   16_16_booth (30.3%), eq.atree.braun
#                                   (28.4%), ezfact64_6 (22.2%),
#                                   pyhala-braun-sat (16.8%)
#
# So on the ISCAS circuits and toughsat the translator has essentially
# finished its job and a better cut would buy nothing; on the multiplier,
# miter and factoring families a fifth to a third of all conflicts are still
# landing in clauses nobody compiled.  That is the target, and it is the
# same set of families the 16-24% table share flagged in
# boxes_eff_study_2026-09-18.txt.
#
# The sobering half: on those same families 48-56% of conflicts are in
# LEARNED clauses.  Absorbing every residual original clause would still
# leave the majority of this run's failures in derived clauses.  That figure
# is not a hard bound -- absorbing the residual changes the search, so the
# learned clauses would be different ones -- but it does say the translator
# is optimising a minority term on the instances where it has room at all.
#
# Concentration argues against the "find a few especially powerful boxes"
# framing, at least among cones as currently cut: on the interesting
# families EVERY box fails (152/152, 470/477, 308/308), with the busiest
# 10% carrying half to two thirds.  Failure is spread across the whole
# compiled structure rather than concentrated in a few tables.  If there is
# powerful structure to mine, it is in the residual clauses above, not in a
# subset of the boxes already built.
