# Verdict over the 29 instances:
#
#   failing box had MORE live rows than the mean (§3.4's rule backwards)  18/29
#   tighter-half concentration by fraction alive (for the premise)         8/29
#   failing box was a BIGGER table than the mean                          26/29
#   top1 by fraction: max 1.9%, median 0.1%
#   conflicts inside tables: min 16%, median 73%, max 92%
#
# So the raw rule §3.4 names is contradicted; the normalised version it
# does not name survives on under a third of instances and flips sign
# within a family (c3540 K=8 concentrates 57.7% of conflicts in the tighter
# half, K=12 only 34.8%); and an argmin rule is hopeless either way.  The
# one consistent pattern is that failing boxes are BIGGER tables (26/29),
# which is an exposure effect -- a bigger table touches more variables and
# so takes part in more conflicts -- not a constrainedness effect.  That is
# the term dom/wdeg normalises away, and it is static information already
# available without any of this machinery.
#
# Scope worth keeping in view: on eq.atree.braun, ezfact64_6 and the
# 16_16_booth multipliers only 16-24% of conflicts happen in a table at
# all.  On those families -- the factoring and multiplier ones the backend
# most wants to win -- four conflicts in five are in clauses, where a box
# heuristic has nothing to say whatever its quality.
