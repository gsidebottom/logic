=== 1.60 x 1.06 = 1.70: the gap is 94% SEARCH QUALITY, 6% throughput ===
#
# We propagate at CaDiCaL's speed -- 83-119k conflicts/s against its 89-113k,
# ratio ~1.0 on every instance.  That rules out memory layout, watch schemes
# and codegen as the primary lever before anyone spends weeks there.
#
# And the deficit is BIMODAL, not uniform.  We match or beat CaDiCaL on
# nearly half the corpus:

#
#                      ours        cadical
#   conflicts         99242          39303

# Clause size matches.  Propagation rate matches.  And every CaDiCaL-ward
# knob we own makes us WORSE on this instance:
#
#   default                    99242 conflicts
#   BOXES_SHRINK=1            114432   (shrinking works -- 28630 blocks,
#                                       61947 literals -- and costs 15%)
#   BOXES_STABLE=1            117777   (restart interval 23.6, close to
#                                       CaDiCaL's 19.75, and 19% worse)
#   BOXES_SHRINK+STABLE       116726
#   BOXES_USED+PROMOTE        113772   (the reduce grace period)
#
# The constants match too: CaDiCaL's scorefactor is 950 per mille -- 0.95,
# exactly our hardcoded var_inc decay -- its restartint is 2 against our
# `conflicts_here >= 2`, its focused restart margin 10% against our 1.10.
# `--bumpreason` is the one thing it does that we do not, and the ablation
# says it HURTS on this very family (0.49-0.71x), so we are already on the
# better side of it.

# Most telling: `--plain` on c3540_k8 is 0.69x, so CaDiCaL is BETTER with
# all pre/inprocessing off -- about 27k conflicts.  Two solvers reduced to
# core CDCL, same decay, same restart trigger, same clause sizes, same
# propagation rate, and it still needs 3.7x fewer conflicts.
#
# The remaining difference is not a feature, a constant, or a knob that
# either codebase exposes.  It is in how the pieces interact, and nothing
# measured here localises it further.  Anyone resuming this should start by
# instrumenting learned-clause LBD (we do not report it, and shrinking's
# whole point is lowering it) rather than porting anything else.
