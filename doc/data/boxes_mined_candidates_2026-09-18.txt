# Mining box candidates out of the clauses the search fails on (2026-09-18)
#
# `sat -b boxes` with BOXES_EFF_STUDY=1 BOXES_EFF_DUMP=<file> writes every
# conflict-carrying clause; tools/mine_boxes.py groups them greedily under a
# variable budget and scores each candidate the only way that matters:
#
#     a box gives GAC on the CONJUNCTION of its clauses;
#     unit propagation gives arc consistency on each clause SEPARATELY.
#
# +lits = mean literals the table forces that UP does not, per sampled
# partial assignment.  gap% = share of samples where the table won at all.
# A group with gap% ~ 0 propagates nothing its clauses already do, however
# much conflict mass it carries -- which is why conflict count alone is the
# wrong thing to mine on.
#
# The scorer is gated on a known value (`tools/mine_boxes.py --selftest`):
# a full adder's gate CNF, the repo's own example of an encoding that loses
# propagation, must show a gap.  It scores 8 rows of 256, +0.25 literals,
# table wins 15.8% of samples.  Read every number below against that.

# Reading it.
#
# ezfact64_6 has real compilable structure.  Group 0 -- 16 variables, 27
# clauses, 1036 rows of 65536 -- scores +0.47 literals and wins 27.2% of
# samples, close to TWICE the full adder's gap, and four more groups land
# between 11% and 18%.  These are tables of 384-1300 rows: entirely
# practical to compile.
#
# 16_16_booth and eq.atree.braun are weak but not empty (best 8.5% and
# 7.0%, the latter with a conflict gap UP misses).  pyhala-braun-sat is
# nearly nothing, and c3540 K=8 is flat zero across every group -- which
# matches its 0.6% original-clause conflict share.  So the direction is
# alive exactly where the conflict-source split said it would be, and
# nowhere else.
#
# Two internal checks worth noting.  eq.atree group 0 is a SINGLE 15-literal
# clause, 32767 rows of 32768, and scores exactly 0.0% -- correct, since UP
# is already GAC for one clause, and a scorer that found a gap there would
# be broken.  And tightness tracks power as the theory says: every group
# with rows/2^n above 0.1 scores under 2%, while the gaps live at 0.004-0.02.
#
# What this does NOT show.  Each group carries 0.15-2.0% of conflicts, so
# the eight groups together address under a tenth of the search's failures.
# The gap is measured under uniform random partial assignments, not the
# distribution the search actually visits, so a gap that exists may never be
# triggered.  And propagation strength costs time: whether any of this
# converts to a faster solve is untested, and the only test that settles it
# is emitting these tables into boxes.json and measuring.
