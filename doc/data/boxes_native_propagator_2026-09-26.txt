# A native table propagator inside CaDiCaL's propagate loop (2026-09-26)
#
# The question the IPASIR-UP results left: do the tables lose to clauses, or
# does the interface -- a call-back per propagation, notifications, polling,
# and every observed variable frozen against elimination -- lose to clauses?
#
# === 1. The control: plain CaDiCaL with the cone variables frozen and no tables ===
#
# Same binary, one at a time, 300 s cap.  (n) = variables frozen.
#
# instance                     |                 plain |           plain + frozen (n) |               + cones
# c3540                        | UNSAT    0.5s    28007 | UNSAT    0.3s    24718 (  645) | UNSAT    1.2s    70441
# ezfact64_6.shuffled-as.sat05 | SATIS   19.9s   444532 | SATIS   20.3s   425072 ( 1090) | SATIS   17.1s   336280
# pyhala-braun-sat-40-4-03     | SATIS   24.6s   455202 | SATIS   26.5s   438438 ( 5832) | SATIS  142.0s  1486553

# toughsat_factoring_895s      | SATIS  109.1s  2047858 | SATIS   93.0s  1674379 (  948) | SATIS   52.2s   891231

# toughsat_24bits_0            | SATIS  103.5s  1702904 | SATIS  143.9s  2090080 (   77) | SATIS   78.5s  1396870
#
# Freezing alone costs 8-15% on pyhala (24.6 -> 26.5 s, 52.6 -> 60.8 s),
# nothing on c3540 and ezfact, 6x on toughsat_958s (10.4 -> 64.9 s -- a
# satisfiable instance whose trajectory changes when 846 variables are
# kept from elimination) and 40% on 24bits; the interface arm costs 2.4x
# on c3540, 5.8x on pyhala-sat, 2.3x on pyhala-unsat.  So the interface,
# not the freezing, is most of the loss, and a native propagator has room.
#
# === 2. The native propagator (src patches in vendor/cadical-3.0.1, `--boxes-native`) ===
#
# Tables live in Internal: kill masks per (variable, value), per-variable
# occurrence lists.  At the end of propagate ()'s loop body the assigned
# variable's tables are visited; a table's live rows are recomputed from
# the current values (no undo); a forced literal is assigned with the
# external_reason sentinel and its reason built lazily at analysis (a
# trail-order cover of the rows not specifying the forced value, through
# the external-clause path), or, at the root, assigned as a unit; a dead
# table becomes a learned conflict clause built directly (a one-literal
# cover: backtrack to the root and a unit; at the root: the empty clause).
# Table variables are frozen and activated; lucky phases are skipped, as
# for an external propagator.  Three defects found by the brute-force
# test on the way: reasons targeting only the rows specifying the
# opposite value (rows leaving the variable unspecified must be dead
# too); table-only variables never decided (unused, so never assigned,
# so SAT with the table unchecked); and re-entrancy -- a unit installed
# through the clause path propagates inside the hook and corrupts the
# clause under construction (the trace showed the nested clause [-7 1 7]
# skipped as satisfied).  Gates: 400 random table-and-clause instances
# against brute force; 60 larger random instances with inprocessing on,
# native against the external propagator, 0 disagreements; the suite.
#
# === 3. Two defects the corpus found that the gates had not ===
#
# 3a. Compaction.  The first native-arm run segfaulted at 0.2 s on ezfact,
# pyhala and toughsat, answered c3540/strassen/sun56 "UNSAT" at 2002-2009
# conflicts, and failed the model check on the w5_ap rows.  CaDiCaL
# renumbers its internal variables at the root once 10% are inactive and
# 'compactint' (2000) conflicts have passed; the tables keep internal
# indices (TTable::vars, tocc, treason) and were not remapped, so the first
# compaction turned every table into a random one -- an empty clause on the
# UNSAT rows (the right verdict from a wrong proof), a crash or a wrong model
# elsewhere.  Fix: no compaction while tables exist (compacting () returns
# false).  What that costs plain CaDiCaL on the control set, one run each:
#
# instance                     |          plain (default) |          plain compact=0
# c3540                        |   UNSAT    0.3s    28007 |   UNSAT    0.3s    28358
# ezfact64_6.shuffled-as.sat05 |   SATIS   21.8s   444532 |   SATIS   94.1s  1596862
# pyhala-braun-sat-40-4-03     |   SATIS   27.4s   455202 |   SATIS    0.9s    15294
# pyhala-braun-unsat-40-4-02   |   UNSAT   57.7s   976129 |   UNSAT   66.0s  1072516
# toughsat_factoring_895s      |   SATIS  118.6s  2047858 |   SATIS   54.4s  1061580
# toughsat_factoring_958s      |   SATIS   11.0s   266526 |   SATIS   90.1s  1641119
# toughsat_24bits_0            |   SATIS  111.9s  1702904 |   SATIS  111.2s  1702904
#
# On the one unsatisfiable row compaction is worth 14% (57.7 vs 66.0 s;
# 60.2 vs 60.5 us per conflict at an equal budget of 200K conflicts, so it
# is the trajectory, not the throughput); on the satisfiable rows the
# trajectory swings 4x either way (pyhala-sat 27 -> 0.9 s, 958s 11 -> 90 s).
# Single-run wall clock on satisfiable instances says nothing about the
# propagator; the per-conflict cost at an equal budget does.
#
# 3b. Visiting at every assignment.  With compaction off the native arm
# ran, and lost everywhere: pyhala-sat, pyhala-unsat, 895s and 958s all at
# the 300 s cap (plain 27/58/119/11 s, the interface arm 145/121/50/30 s).
# At an equal budget of 200K conflicts on pyhala-unsat (an UNSAT instance,
# so no trajectory luck), `--cadical-limit conflicts=200000`:
#
# arm              wall   us/conflict  propagations  learned lits   tables: visits  forced  reasons
# plain            11.7s     58.4        97.7 M         43.8
# IPASIR-UP        26.5s    132.5       170.0 M         48.1
# native, eager   121.8s    609.0       131.5 M         52.2          242.5 M   23.4 M   10.7 M
# native, fixpoint 21.9s    109.3       137.8 M         44.0           55.5 M    0.7 M    0.14 M
#
# The eager hook (visit a table at every assignment of one of its
# variables, inside the propagate loop) forced 117 table literals per
# conflict where the external propagator, asked only at the fixpoint of
# clause propagation, forced 0.6: firing first, it pre-empted the learned
# clauses that would have implied the same literals for free, and every
# pre-empted literal that analysis touched needed a lazily built reason
# clause -- 53 per conflict, 10.7 M in the run -- which went into the
# watch lists.  The hook's own time was 20 s and the reasons 8 s of the
# 122 s; the other 94 s were CaDiCaL propagating through the reason
# clauses.  The second design marks an assignment's tables in a touched
# list and visits them when the clause propagation has nothing left (as
# CaDiCaL treats an external propagator): 3.5 forced literals and 0.7
# reasons per conflict, 4.1 s in the hook, and 109 us per conflict --
# 17% under the interface arm, 1.9x plain.  What is left of the gap to
# plain is not the hook (19% of the run) but 41% more propagations per
# conflict (689 vs 488 -- the residual with 858 cones replaced by tables
# is a different instance to search) at the same 0.12-0.13 us each.
# CADICAL_TABLE_EAGER=1 keeps the first design for the A/B;
# CADICAL_TABLE_STATS=1 prints the hook's counters at exit.
#
# The same budget on toughsat_895s (K=12 cones; the interface arm's best
# win in step 2, 109 -> 50 s):
#
# arm              wall   us/conflict  propagations  learned lits   tables: visits  forced  reasons
# plain             7.9s     39.6        54.0 M         32.8
# IPASIR-UP        10.8s     53.8        28.0 M         33.8
# native, fixpoint 11.4s     56.9        25.2 M         33.2           17.6 M    1.0 M   0.16 M
#
# Here the native arm is 6% slower per conflict than the interface arm
# (hook 1.6 s of 11.4), and both are 1.4x plain per conflict while doing
# half plain's propagations: the tables replace a lot of clause
# propagation on these wide cones, and the per-conflict work that is left
# (analysis, minimisation, bumping, reduce) is the same in every arm.  The
# 2x wall-clock win of step 2 was 891K conflicts against 2.05M -- a
# trajectory, not a throughput.
#
# And freezing alone at the same budget (plain, cone variables frozen, no
# tables): pyhala-unsat 58.1 us/conflict (plain 58.4), toughsat_895s 41.4
# (39.6).  So at an equal budget: plain = frozen < native = interface at
# 1.4x (895s) to 1.9-2.3x (pyhala-unsat) plain.  Section 1's reading --
# "the interface, not the freezing, is most of the loss" -- was wrong: the
# interface is 0-20% of it, the freezing none, and the rest is the tables'
# propagation itself, which the learned clauses make mostly redundant.
#

# === 4. Verdict ===
#
# The interface was not the loss.  Done natively, with the visits at the
# fixpoint where CaDiCaL puts an external propagator's, the tables cost
# what they cost through IPASIR-UP, within 20% either way: 1.5-2x plain
# per conflict wherever they fire, level with plain where they do not.
# The wall-clock wins over plain in the table (pyhala-sat 9.8 s against
# 24.6, 24bits 88 against 104, 958s and 895s in step 2) are trajectories
# on satisfiable instances, of the size that switching compaction off
# produces on its own (section 3a); every unsatisfiable row loses --
# c3540 3.8x, pyhala-unsat 2.4x, mm(2;6) 2.7x, w5_ap(178) 2.9x -- because
# there the per-conflict cost is the result.  A compact-table hook
# (incremental masks, scan only the tables whose live set changed) would
# take perhaps a third off the hook, which is 4-28% of a cone run and 72%
# of a waerden run; it cannot reach plain, because the cost that remains
# is the search doing 1.4x the propagations per conflict through a
# residual whose structure the learned clauses now have to rediscover.
# Small tables are clauses.  The box track's open item on the native
# propagator is closed with this: tables do not beat CaDiCaL's clauses on
# what CaDiCaL can already solve; the remaining question is the 76
# unsolved balanced instances, where a trajectory that never converges
# might be changed by cones -- a different experiment, scored on solves.
