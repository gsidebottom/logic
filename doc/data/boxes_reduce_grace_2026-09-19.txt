# CaDiCaL's reduce grace period, ported and A/B'd (2026-09-19)
#
# Ported from vendor/cadical-3.0.1 (reduce.cpp, analyze.cpp, clause.cpp):
#
#   BOXES_USED=1     `bump_clause` sets used = MAX_USED (31) on every clause
#                    conflict analysis resolves.  reduce_db decays it once
#                    per reduction, spares a tier-1 clause (LBD <= keep_lbd)
#                    that was used within the last 31 reductions and a
#                    tier-2 clause (LBD <= BOXES_TIER2_LBD, default 6) only
#                    if used since the PREVIOUS reduction, then drops
#                    BOXES_REDUCE_TARGET% (75) of what is left as CANDIDATES
#                    -- not a fraction of the whole database, which is the
#                    blunter pool our default uses.
#   BOXES_PROMOTE=1  also recomputes a resolved clause's LBD against the
#                    current trail and promotes it when the glue shrank, so
#                    a clause is not judged once, at birth.
#
# Both default OFF.  120 s cap, one solver at a time, all 21 instances in
# the A/B corpus except eq.atree.braun.13 (times out in every arm).
# Verdicts captured and identical everywhere -- a reduce bug shows up as a
# wrong answer, not a slow one.

=== What this says ===
#
# NEUTRAL.  The 8% headline is carried entirely by the four SAT instances
# (w55_177 0.89s -> 0.33s, r3sat_5 0.98s -> 0.31s), which is the same
# trajectory volatility that produced a 0.489x artifact in the CaDiCaL-side
# ablation and reversed on an UNSAT-weighted set.  On the sixteen
# refutations, whose times are stable enough to read, the port is worth
# 0.978x with the counter alone and 1.023x with promotion -- nothing.
#
# The 1.30x that motivated building this measured what CaDiCaL LOSES by
# giving up a grace period its whole reduce machinery is tuned around
# (dynamic percentile tiers, its own target, its interval schedule).  What
# our engine GAINS by adopting one piece is a different quantity, and this
# is it.
#
# One sub-finding that is consistent and worth keeping: the two halves are
# ONE mechanism.  Sparing clauses without re-judging their glue keeps the
# wrong ones --
#
#   instance        off      used   used+prom      (conflicts)
#   w55_178         868k     1088k       784k
#   c3540_k8_s3     132k      160k       130k
#
# -- and promotion recovers it.  That is why CaDiCaL sets `used` inside
# `bump_clause`, in the same breath as recomputing the glue, rather than in
# two places.  If this is ever turned on, it goes on as a pair.
#
# Default stays off: no measured benefit, and it costs an LBD recomputation
# per resolved clause in conflict analysis.
