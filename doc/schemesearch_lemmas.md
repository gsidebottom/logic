# Learned rank certificates for the scheme search (stage 4b design)

2026-08-29. The CDCL analog for the product-level UNSAT search
(src/bin/schemesearch3.rs): turn each theory refutation into a reusable,
cheaply-evaluable certificate — the theory-lemma learning that plain DFS
lacks. This is the design that could change the search's growth rate;
everything before it (propagators, symmetry) changed constants.

## The conflict object

A Koszul refutation at residual R proves rank(R) > k via
rank(K_p(R)) ≥ v, certified by an invertible v×v minor: row set I,
column set J of the wedge matrix K_p (side s, parameter p), with
bound(R) = ceil(v / D) > k, D = C(8, p). Today that minor is found by
Gaussian elimination and thrown away. The lemma keeps it:

    L = (s, p, I, J, v, R_base)

## Why it transfers to other nodes

K_p is LINEAR in the tensor: K(R') = K(R_base) xor K(Δ) where
Δ = R_base xor R' is the XOR of the product masks on which the two
paths differ. Restricted to the minor:

    rank(K(R')[I,J]) ≥ v − rank(K(Δ)[I,J])
    bound(R') ≥ ceil((v − rank(K(Δ)[I,J])) / D)          (sound)

## Why evaluation is ~100–250× cheaper than fresh Koszul

For a rank-one product m = α⊗β⊗γ the wedge matrix factors:
row(S',k) = γ_k · u(S'), so K(m)'s row space is spanned by ≤ D
explicitly constructible generators. K(Δ)[I,J] for |Δ| products is
generated by ≤ D·|Δ| restricted vectors; its rank costs one GE over
≤ D·|Δ| rows × |J| columns ≈ 5–20 µs, versus ~5 ms for fresh Koszul
(full 1134×1134 build + eliminate). The trivial no-computation form
(v − D·|Δ|) is just bound monotonicity and adds nothing; the value is
exactly in evaluating the restricted perturbation.

## Search integration (CDCL dictionary)

- decision        = product choice (already symmetry-reduced)
- propagation     = flatten / 1-ply probe / Koszul / lemma evals
- conflict        = rank refutation at a node
- conflict analysis = minor extraction from the refuting GE
- learned clause  = the minor lemma L (globally valid, µs-evaluable)
- clause activity = try most-recently-learned lemmas first, cap ~4–8
                    per node; fall back to fresh Koszul; learn on every
                    fresh refutation

Store: per level-1 branch first (Δ stays small within a branch — the
restricted-perturbation cost scales with |Δ|); a global store indexed by
locality is the later refinement.

## Free byproduct: proof logging

A lemma IS a checkable proof object (minor + value + base path). The
per-node refutation reason (which lemma or fresh minor, plus the
arithmetic) is exactly the proof log the r=20 frontier requires. The
verifier re-checks minors and restricted-perturbation ranks — no
re-search. Building 4b therefore builds most of the certification
story too.

## Implementation plan

1. koszul_side returns the refuting minor (track pivot rows/columns in
   the elimination; I from the echelon's pivot row origins, J from
   pivot columns).
2. Lemma struct + per-root store; generator construction for
   K(m)[·,J] from (α, β, γ) directly.
3. dfs: lemma evals (bounded count) → fresh Koszul → learn.
4. Gates: rungs 9–14 must reproduce byte-identically with lemmas on
   (they prune at level 1 before lemmas matter); r=15/16 are the
   measurement rungs.
5. Ablation: nodes and wall with lemmas off/on at fixed budget — the
   stage-4 analog of the 746× and 632384× numbers.

## Risks

- Minor transfer decay: if K(Δ)[I,J] ranks are typically ≥ D·|Δ|·0.9,
  lemmas barely beat monotonicity — measure the decay curve first on
  sampled sibling pairs before building the store machinery.
- Store discipline: unbounded lemma lists burn the µs budget; activity
  caps from day one.
